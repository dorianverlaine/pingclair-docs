スループットの数字は、それを生んだ条件と並べて初めて意味を持ちます。このページでは最新の比較結果と、その隣に、結果が示す範囲を制限するすべての条件を載せています。

## 🧭 比較の方法

- **バージョン。** Pingclair `v0.2.0-rc.3`（リリースバイナリ）、nginx 1.31.6、Caddy 2.11.4。
- **ホスト。** OrbStack を動かす Apple M2 のノートパソコン 1 台。
- **制限。** どのサーバーも 2 CPU に制限したコンテナで動かし、ワーカー数と 1 KiB のペイロードを揃えています。
- **構成。** リバースプロキシのバックエンドは、同じ Docker ネットワーク上の専用コンテナで動かしています。
- **負荷生成ツール。** HTTP/1.1、HTTPS/1.1、HTTP/2 にはネイティブの `h2load` を使います。HTTP/3 には、同じ Docker ネットワーク内で ngtcp2 対応の `h2load` を使います。

## 📊 結果

各値は 1 秒あたりのリクエスト数で、50,000 リクエストを交互に 3 ラウンド実行した中央値です。すべてのリクエストが成功した行だけを有効としています。

| シナリオ | Pingclair | nginx 1.31.6 | Caddy 2.11.4 |
| --- | ---: | ---: | ---: |
| HTTP/1.1 静的配信 | 46,125 | 39,478 | 18,266 |
| HTTPS/1.1 静的配信 | 40,721 | 31,508 | 19,978 |
| HTTP/2 静的配信 | 92,369 | 41,972 | 17,424 |
| HTTP/3 静的配信 | 56,180 | 55,638 | 22,912 |
| HTTP/1.1 リバースプロキシ | 20,856 | 22,584 | 17,117 |
| HTTPS/1.1 リバースプロキシ | 20,297 | 21,944 | 16,660 |
| HTTP/2 リバースプロキシ | 23,181 | 20,396 | 未完了 |
| HTTP/3 リバースプロキシ | 28,078 | 22,213 | 未完了 |

nginx と比べると、Pingclair は HTTP/1.1、HTTPS/1.1、HTTP/2 の静的配信の行で上回っており（それぞれ 1.2 倍、1.3 倍、2.2 倍）、HTTP/3 の静的配信はほぼ互角です。リバースプロキシの負荷では、HTTP/2 で 14%、HTTP/3 で 26% 上回る一方、HTTP/1.1 と HTTPS/1.1 は nginx より約 8% 下回っています。

## 📐 この数字を制限する条件

- **ホストはノートパソコンです。** 絶対的なスループットは処理能力を主張するものではなく、比率はこの管理された負荷のもとでの相対的な性能だけを表します。
- **比較は行の中で行ってください。** HTTP/3 の負荷生成ツールは他とは異なる環境で動いているため、絶対的なスループットをプロトコル間で比べることはできず、比べられるのは同じ行の中のサーバー同士だけです。
- **未完了の行は比較ではありません。** このホストとハーネスでは、Caddy はプロキシの HTTP/2 と HTTP/3 の行を完了できませんでした。試験した並行数では、アップストリーム接続の入れ替わりがコンテナで利用できるエフェメラルポートを使い果たしたためです。これらのセルは、別の負荷で測り直すのではなく、未完了として報告しています。
- **結果はホストに依存します。** サーバー同士の相対的な位置は、CPU アーキテクチャ、カーネル、ワーカー数、TLS の実装によって変わります。
