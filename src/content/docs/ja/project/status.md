このページは、デプロイの前に 1 つの問いに答えます。現在のリリースは必要なことをこなせるか、そしてどこで限界に達するか、です。対象は最新の公開リリースである **v0.2.0-rc.3** です。

## 📌 現在のリリースはリリース候補

現在のリリースは **v0.2.0-rc.3** です。その[リリースノート](https://github.com/dorianverlaine/pingclair/releases/tag/v0.2.0-rc.3)に、変更点とタグ付け時点で判明していた不具合が載っています。

`v0.1.x` 系はメンテナンスされていません。修正、バックポート、セキュリティアドバイザリのいずれも提供されません。アップグレードしてください。`v0.1.x` は Admin API の `api_key` フィールドを解析するだけで一度も読まなかったため、その Admin API は誰も認証していませんでした。

## ✅ このリリースが対応しているもの

| 領域 | 対応内容 |
| --- | --- |
| プロトコル | 1 つの設定から、TCP 上の HTTP/1.1 と HTTP/2、QUIC 上の HTTP/3。 |
| TLS | ACME による公開証明書の自動取得、永続的な内部認証局、自分で用意した証明書ファイル。 |
| 静的ファイル | `zstd` と `gzip` による圧縮、レンジリクエスト、条件付きリクエストを伴うファイル配信。 |
| リバースプロキシ | 複数のアップストリーム、複数のロードバランシングポリシー、アクティブヘルスチェック、バックアップのアップストリーム。 |
| FastCGI | HTTP/1.1 と HTTP/2 での `php_fastcgi`。 |
| レート制限 | マッチャー単位の、正確なローカルレート制限。 |
| 可観測性 | ローテーション付きのアクセスログと Prometheus メトリクス。 |
| 管理 | 状態の確認と設定の再読み込みのための Admin API。 |

## 🛡️ サーバーが意図的に拒否する名前

Caddyfile 形式は、Pingclair が実装しているより多くの名前を定義しています。サーバーが満たせない名前は、ファイルの読み込み時に、欠けている機能を示すメッセージとともに拒否されます。それを含む設定は起動しません。読者からよく尋ねられる名前は次のとおりです。

- `map`、`invoke`、`tracing` ディレクティブ。
- `storage` オプション。証明書と状態はローカルディスクにしか置かないためです。
- `on_demand_tls` と `ocsp_stapling` オプション。
- `handle_errors`。カスタムエラーページには代わりに `error_page` を使います。
- `encode br`。ストリーミング対応の Brotli エンコーダーが無いためです。

完全な一覧はサーバーリポジトリの README にあります。README に記載の無い名前をパーサーが拒否するとそこでテストが失敗するため、一覧がコードより遅れることはありません。

## ⚠️ 既知の制限

- **証明書ストレージはローカルです。** ストアはディスク上のディレクトリなので、複数のインスタンスで 1 つの証明書ストアを共有することはできません。
- **このリリースでは DNS-01 が完了しません。** `tls { dns cloudflare <token> }` とグローバルの `acme_dns` オプションは Cloudflare であれば受け付けられ、それ以外のプロバイダーは名前を挙げて拒否されます。しかし v0.2.0-rc.3 では、TXT レコードに誤った値が入るため、DNS-01 の注文はすべて `Invalid` で終わります。修正は `main` にあります（[HTTPS](/ja/start/https/#-dns-01-とワイルドカード)）。
- **HTTP/3 にはトレーラーもトンネルもありません。** 宣言されたリクエストトレーラーはどのプロトコルでも拒否され、HTTP/3 は `CONNECT` をリセットします（[アーキテクチャ](/ja/concepts/architecture/#-プロトコルごとの違い)）。
- **HTTP/3 上の FastCGI は `501` を返します。**
- **負荷がかかると WebSocket のアップグレードが断続的に失敗します。** 忙しいマシンでは約 10〜15% です。原因は上流の `pingora-proxy` crate の競合状態で（[cloudflare/pingora#946](https://github.com/cloudflare/pingora/issues/946)）、アイドル状態のマシンではまず再現しません。

## 🔁 次のリリースで変わること

以下の変更は `main` にあり、v0.2.0-rc.3 には含まれていません。いくつかはアップグレード時に挙動を変えます。[CHANGELOG](https://github.com/dorianverlaine/pingclair/blob/main/CHANGELOG.md) の Unreleased に、アップグレードノートとともにすべて記載されています。

- **ルートの順序が Caddy に従います。** どのルートが応答するかは、最も具体的なパスではなくディレクティブの順序で決まります（[設定モデル](/ja/concepts/configuration/#-どのルートがリクエストに応答するか)）。
- **圧縮は `encode` で指定した場合にだけ行われます。** `encode` の無いサイトは、ファイルを圧縮せずに配信します。
- **リクエストボディの既定の上限がなくなります。** 1 MiB の既定値は廃止されます。それに頼っていた場合は `request_body { max_size … }` を設定してください。
- **`remote_ip` と `client_ip` が区別されます。** `remote_ip` は接続のピアに、`client_ip` は `trusted_proxies` を適用した後のクライアントにマッチします。Pingclairfile でクライアントを遮断するには、`client_ip` でマッチさせて `abort` します。`blocked_ips` は JSON の設定にしかありません。
- **`CONNECT` と `TRACE` には `405` を返します。** どのプロトコルでも `Allow` ヘッダーが付きます。
- **HSTS が接続に従います。** `Strict-Transport-Security` は暗号化されたレスポンスにだけ送られ、Pingclairfile では `header Strict-Transport-Security "max-age=…"` で有効にします。
- **停止がグレースフルになります。** `SIGTERM` を受けると、処理中のリクエストが `grace_period`（既定 30 秒）以内に完了するのを待ちます。
- **admin や HTTP/3 のポートが使用中なら起動を中止します。** ログに記録するだけで済ませることはなくなります。
- **ゲートウェイエラーが発生元を示します。** Pingclair が生成した `502` や `504` には `Proxy-Status` ヘッダーが付きます。
- **DNS-01 が動作します。** ワイルドカードのサイトは 1 枚のワイルドカード証明書を注文します。
- **`storage file_system <path>` と `ocsp_stapling off` を受け付けます。**
- **内部認証局が Caddy の配置に移ります。** 旧来の認証局は移行されません。新しいルートが作成されるため、クライアントはそれを信頼し直す必要があります。
