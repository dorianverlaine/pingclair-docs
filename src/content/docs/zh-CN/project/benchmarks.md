吞吐量数字只有和产生它的条件放在一起才有意义。本页给出最新的比较结果，并在旁边列出限制其含义的每一个条件。

## 🧭 比较是如何进行的

- **版本。** Pingclair `v0.2.0-rc.3`（发布版二进制文件）、nginx 1.31.6 和 Caddy 2.11.4。
- **主机。** 一台运行 OrbStack 的 Apple M2 笔记本电脑。
- **限制。** 每个服务器都运行在限制为两个 CPU 的容器中，worker 数量相同，负载都是 1 KiB。
- **拓扑。** 反向代理的后端运行在同一个 Docker 网络中的独立容器里。
- **负载生成器。** HTTP/1.1、HTTPS/1.1 和 HTTP/2 使用原生的 `h2load`。HTTP/3 使用在同一个
  Docker 网络中运行、启用了 ngtcp2 的 `h2load`。

## 📊 结果

每个值都是每秒请求数：三轮交错进行、每轮 50,000 个请求的中位数。只有所有请求都成功时，这一行才算数。

| 场景 | Pingclair | nginx 1.31.6 | Caddy 2.11.4 |
| --- | ---: | ---: | ---: |
| HTTP/1.1 静态文件 | 46,125 | 39,478 | 18,266 |
| HTTPS/1.1 静态文件 | 40,721 | 31,508 | 19,978 |
| HTTP/2 静态文件 | 92,369 | 41,972 | 17,424 |
| HTTP/3 静态文件 | 56,180 | 55,638 | 22,912 |
| HTTP/1.1 反向代理 | 20,856 | 22,584 | 17,117 |
| HTTPS/1.1 反向代理 | 20,297 | 21,944 | 16,660 |
| HTTP/2 反向代理 | 23,181 | 20,396 | 未完成 |
| HTTP/3 反向代理 | 28,078 | 22,213 | 未完成 |

与 nginx 相比，Pingclair 在 HTTP/1.1、HTTPS/1.1 和 HTTP/2 静态文件这三行领先（分别为 1.2 倍、1.3 倍和
2.2 倍），HTTP/3 静态文件则基本持平。在反向代理负载上，它在 HTTP/2 上领先 14%，在 HTTP/3 上领先 26%，
而 HTTP/1.1 和 HTTPS/1.1 仍比 nginx 落后约 8%。

## 📐 限制这些数字的条件

- **主机是一台笔记本电脑。** 绝对吞吐量不代表容量承诺，这些比例只描述在这个受控负载下的相对性能。
- **只在同一行内比较。** HTTP/3 的负载生成器运行环境与其他不同，所以不应跨协议比较绝对吞吐量，
  只应在同一行内比较各个服务器。
- **未完成的行不构成比较。** 在这台主机和这套测试工具上，Caddy 没有完成反向代理的 HTTP/2 和 HTTP/3 两行：
  在所测的并发度下，频繁新建的上游连接耗尽了容器可用的临时端口。这些单元格标为未完成，
  而不是换一种负载去测量。
- **结果取决于主机。** 各服务器的相对位置会随 CPU 架构、内核、worker 数量和 TLS 实现而变化。
