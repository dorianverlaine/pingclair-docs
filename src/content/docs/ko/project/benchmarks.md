처리량 수치는 그것을 만든 조건과 함께 있을 때만 의미가 있습니다. 이 페이지는 최신
비교 결과와 함께, 그 결과가 보여 주는 범위를 제한하는 모든 조건을 제시합니다.

## 🧭 비교 방법

- **버전.** Pingclair `v0.2.0-rc.3`(릴리스 바이너리), nginx 1.31.6, Caddy
  2.11.4입니다.
- **호스트.** OrbStack을 실행하는 Apple M2 노트북 한 대입니다.
- **제한.** 모든 서버는 CPU 2개로 제한한 컨테이너에서 실행되며, 워커 수와 1 KiB
  페이로드가 같습니다.
- **구성.** 리버스 프록시 백엔드는 같은 Docker 네트워크의 별도 컨테이너에서
  실행됩니다.
- **부하 생성기.** HTTP/1.1, HTTPS/1.1, HTTP/2는 네이티브 `h2load`를 씁니다.
  HTTP/3는 같은 Docker 네트워크 안에서 ngtcp2를 지원하는 `h2load`를 씁니다.

## 📊 결과

각 값은 초당 요청 수이며, 50,000개 요청을 교차로 세 차례 실행한 결과의
중앙값입니다. 모든 요청이 성공한 행만 인정합니다.

| 시나리오 | Pingclair | nginx 1.31.6 | Caddy 2.11.4 |
| --- | ---: | ---: | ---: |
| HTTP/1.1 정적 파일 | 46,125 | 39,478 | 18,266 |
| HTTPS/1.1 정적 파일 | 40,721 | 31,508 | 19,978 |
| HTTP/2 정적 파일 | 92,369 | 41,972 | 17,424 |
| HTTP/3 정적 파일 | 56,180 | 55,638 | 22,912 |
| HTTP/1.1 리버스 프록시 | 20,856 | 22,584 | 17,117 |
| HTTPS/1.1 리버스 프록시 | 20,297 | 21,944 | 16,660 |
| HTTP/2 리버스 프록시 | 23,181 | 20,396 | 완료되지 않음 |
| HTTP/3 리버스 프록시 | 28,078 | 22,213 | 완료되지 않음 |

nginx와 비교하면 Pingclair는 HTTP/1.1, HTTPS/1.1, HTTP/2 정적 파일 행에서 각각
1.2배, 1.3배, 2.2배 앞서며, HTTP/3 정적 파일은 사실상 대등합니다. 리버스 프록시
부하에서는 HTTP/2에서 14%, HTTP/3에서 26% 앞서지만, HTTP/1.1과 HTTPS/1.1에서는
nginx보다 약 8% 뒤처집니다.

## 📐 이 숫자를 제한하는 조건

- **호스트는 노트북입니다.** 절대 처리량은 용량에 대한 주장이 아니며, 비율은 이
  통제된 부하에서의 상대 성능만을 나타냅니다.
- **같은 행 안에서 비교합니다.** HTTP/3 부하 생성기는 다른 것과 다른 환경에서
  실행되므로, 절대 처리량은 프로토콜 간이 아니라 한 행 안의 서버끼리만 비교해야
  합니다.
- **완료되지 않은 행은 비교가 아닙니다.** 이 호스트와 측정 환경에서 Caddy는
  프록시 HTTP/2와 HTTP/3 행을 완료하지 못했습니다. 시험한 동시성에서 업스트림 연결이
  반복해서 새로 맺어지며 컨테이너의 임시 포트를 소진했기 때문입니다. 이 칸은 다른
  부하로 측정한 값으로 채우지 않고 완료되지 않음으로 표시합니다.
- **결과는 호스트에 따라 달라집니다.** 서버 간 상대 순위는 CPU 아키텍처, 커널, 워커
  수, TLS 구현에 따라 바뀝니다.
